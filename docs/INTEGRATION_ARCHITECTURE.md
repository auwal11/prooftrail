# ProofTrail integration architecture report

## Discovery

ProofTrail is a Next.js 16 App Router application written in TypeScript. API routes live under `src/app/api`, and server-side case/evidence/report logic is in `src/lib`. PostgreSQL is accessed through Prisma 6. Authentication uses hashed HTTP-only session cookies and every existing case/evidence/report route enforces the signed-in user's ownership. Evidence is validated by magic bytes, stored privately, SHA-256 hashed, and processed by `src/lib/evidence-service.ts`. Reports are generated by `src/lib/report/pdf.ts` and downloaded through authenticated routes. Production uses the `main` branch and the existing environment/deployment configuration; no external integration credentials are present in the repository.

The existing case engine requires a `User` owner. The integration layer therefore assigns each authorized external partner to an owning ProofTrail user and creates cases through the same `Case` entity and evidence-processing service. It does not create a second case engine or modify LauPay's transaction engine.

## Integration design

- `IntegrationPartner` stores tenant ownership, an API key lookup hash, encrypted HMAC secret, scopes, active/revoked state, and optional outbound webhook configuration.
- `Case` stores the partner, external transaction/dispute IDs, request ID, and source system while retaining normal ProofTrail ownership checks.
- `IntegrationIdempotency` prevents duplicate dispute creation and rejects the same key for a different request hash.
- `IntegrationDelivery` records outbound event payloads and delivery attempts without storing evidence contents or unnecessary customer data.
- Requests use `X-ProofTrail-Key`, `X-ProofTrail-Timestamp`, and `X-ProofTrail-Signature`. The signature is HMAC-SHA256 over `timestamp.body` (for JSON) or `timestamp.` (for an empty body), and timestamps are limited to five minutes to prevent replay.
- Integration routes use `/api/v1/integrations/disputes` and only return tenant-scoped case metadata.

## Deliberate boundaries

LauPay-reported transaction fields are labeled as external source data. They are not presented as bank-verified facts. The integration API does not accept public file URLs, credentials, OTPs, PINs, or payment-card data. No production credential or live webhook has been provisioned by this change; deployment and authorized end-to-end verification remain separate steps.
